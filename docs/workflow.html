The workflow, end to end

1

Trigger

An external scheduler (cron-job.org) calls the GitHub Actions workflow_dispatch event around 06:30 Zürich time. GitHub spins up an Ubuntu runner, installs Python 3.11 + dependencies, and runs python main.py.

↓
2

Fetch news

NewsFetcher pulls items from 60+ RSS/Atom feeds, each tagged with a trust tier (1 primary/official → 6 community): official company blogs & docs, status pages, government/regulator feeds, wire/business, tech media, research, dev community (Hacker News, GitHub Trending, Reddit), plus thematic-investing and critical-minerals sources. Sources without a usable first-party feed (Anthropic, xAI, Mistral, Reuters, FT, WSJ, policy bodies…) are covered by key-free Google News search feeds. Only items published within the last 48 hours are kept (lookback_hours); items with no date are always kept.

↓
3

Pre-filter, deduplicate & flag continuations

Near-duplicate articles (same story from different outlets) are removed using title word-overlap (Jaccard similarity) before anything reaches the LLM — and the collision is resolved in favor of the most primary source (lowest tier), so the digest links the original announcement rather than a rewrite. Items matching a recently covered story (see step 8) are marked [COVERED]. Each surviving item gets a unique ID (INT-1, DOM-2, …).

↓
4

Stage 1 — Selection (LLM)

All items are sent to the LLM with the stage1_prompt_template. Acting as a "senior AI industry analyst," it returns a JSON array of the 15–20 highest-quality item IDs, balancing categories, following the source-trust hierarchy, applying an explicit avoid-list (SEO farms, copy-paste newsletters, unverified rumors, benchmark screenshots), and skipping [COVERED] continuations unless there's a materially new development. Code validates the IDs and enforces the 15–20 count (with a fallback if parsing fails).

↓
5

Stage 2 — Summarization (LLM)

The selected items are sent back with the stage2_prompt_template. The LLM returns structured JSON per item: category, headline, date, a 4–6 sentence analytical summary, source name, and source URL.

↓
6

Render

Python parses the JSON and builds the digest, enforcing a fixed category order and running a second deduplication pass (so formatting/order never depends on the model behaving). Output is Markdown.

↓
7

Notify

The digest is converted to a styled HTML email and sent via Gmail SMTP to everyone on the distribution list (EMAIL_TO). Other channels — webhook, Slack, Telegram, Discord — can be enabled too. Each configured language is generated and sent separately.

↓
8

Persist history

The published stories are recorded to data/news_history.json (headline + URL, kept for retention_days, default 7). Because the GitHub runner is ephemeral, the workflow commits that file back to the repo — giving the next day's run the cross-run memory it uses in step 3 to tell a genuinely new story from a continuation.

Common questions

Where does the data come from?
From 60+ RSS/Atom feeds (no paid news API), each tagged with a trust tier so selection and dedup can prefer the most authoritative source:
  • 1 · Primary / official — OpenAI, Google AI, DeepMind, Meta AI, Microsoft, NVIDIA, Hugging Face, AWS, github.blog, Apple Newsroom + service status pages (OpenAI, Anthropic, Google Cloud, AWS, GitHub)
  • 2 · Government / regulator — White House, NIST, FTC, and an AI-policy / export-controls search feed
  • 3 · Wire / business — Reuters, Bloomberg, FT, WSJ, Axios
  • 4 · Tech media & verticals — TechCrunch, VentureBeat, MIT Tech Review, Ars Technica, Wired, The Verge, Engadget; plus healthcare, robotics, finance, clean energy/ESG, critical minerals
  • 5 · Research — arXiv (cs.AI, cs.LG, cs.CV, cs.CL), Nature
  • 6 · Community / dev — Hacker News, GitHub Trending, Reddit (r/LocalLLaMA, r/MachineLearning)
  • Localized — Chinese feeds (36Kr, JiQiZhiXin, Leiphone…) for zh; German feeds (Heise, t3n, Golem…) for de
Vendors with no usable first-party feed (Anthropic, xAI, Mistral, Cohere, DeepSeek, Reuters, FT, WSJ…) are reached via key-free Google News search feeds. All defined in src/news/fetcher.py.
What model is used?
The bot is provider-agnostic — it supports Claude, DeepSeek, Gemini, Grok, and OpenAI. This repo is currently configured with provider: gemini and no model override, so it runs on gemini-2.5-flash-lite (the Gemini provider's default). Change provider / model in config.yaml (or the LLM_PROVIDER / LLM_MODEL secrets) to switch.
How are the news stories selected?
In two LLM stages plus code-side guarantees:
  • Stage 1 picks 15–20 items by quality, prioritizing breakthroughs, major launches, policy/regulation, big funding/M&A, balanced category coverage, and thematic-investing relevance. It follows the source-trust hierarchy (primary > regulator > wire > tech media > research > community), honors an explicit avoid-list, skips [COVERED] continuations, and dedupes "same story" items.
  • Stage 2 assigns each item to exactly one category and writes a 4–6 sentence analytical summary.
  • Code enforces the canonical category order, resolves duplicates toward the most primary source, and runs an additional dedup pass, so the final digest is consistent regardless of model quirks.
Both prompts live in config.yaml and are fully editable.
How does it avoid repeating yesterday's news?
Each run records the stories it published (headline + URL) to data/news_history.json and the workflow commits that file back to the repo. On the next run, fetched items matching a story from the last retention_days (default 7) — by normalized URL or title-token overlap — are flagged [COVERED], and Stage 1 drops them unless there's a genuinely new development. Toggle it under news.history in config.yaml.
What categories appear in the digest?
In this fixed order: Thematic Investing Product Launches & Updates Enterprise & Industry Applications Funding & Market Dynamics AI Infrastructure & Hardware Large Language Models & Foundation Models Multimodal AI Robotics & Autonomous Vehicles Policy & Regulation Open Source & Community
How is the task scheduled?
The GitHub Actions workflow (.github/workflows/daily-news.yml) is configured for workflow_dispatch only — it has no internal GitHub cron. An external scheduler, cron-job.org, fires the dispatch daily at roughly 06:30 AM Zürich (≈04:30 UTC summer / 05:30 UTC winter). You can also trigger it manually from the repo's Actions tab → Run workflow.
How is it configured (secrets vs. config)?
  • Secrets (GitHub → Settings → Secrets, or local .env): API keys, NOTIFICATION_METHODS, Gmail credentials, EMAIL_TO distribution list, AI_RESPONSE_LANGUAGE, optional LLM_PROVIDER/LLM_MODEL.
  • config.yaml: provider/model defaults, max_items_per_source, lookback_hours, the history (cross-run memory) settings, and the Stage 1 / Stage 2 prompt templates.
Scheduled runs read GitHub secrets; the local .env only affects runs on your own machine.
What languages are supported?
en — English zh — 中文 de — Deutsch
Prompts are always English; the digest output is produced in each requested language, and a separate notification is sent per language.
